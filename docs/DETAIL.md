# 记忆规则提示

在输入框上方实时提示「与你要做的事相关的记忆规则」。打字停顿后自动出现。

## 功能

- 输入停顿 350ms 后，取草稿最后 300 字做匹配
- 命中则显示 `⚑ 相关规则 N 条`，点开看标题与正文摘要
- 草稿太短（少于 6 字）或没有命中时完全不显示

## 匹配原理

**动作 + 名词两路合并**，不需要模型、不需要标注、不联网：

1. **动作归一化**：14 组动作词表（合并/提交/新增/修改/删除/配置/文档/测试/发布/查询/比价/视频/SQL/接口）。规则原文里的"合并 Release…"和你的"合到 Release"都落到 `merge`。
2. **名词交集 + IDF 加权**：共享的低频词越多分越高；"这个""一下"这类高频词权重自动压低。
3. **准入条件**：草稿必须含动作词，规则也必须含同类动作，且两者有对象层面的词交集——光是"合并"两个字相同不算。
   没有动作词的句子（"现在可以""好的谢谢"）直接忽略，不提示。

## 数据来源

读 `$DSH_HOME/memory/preferences.md` 与 `pitfalls.md`（dsh-mneme 的镜像文件）。

- 只搜「规则/偏好」和「坑」，不含 `decisions.md` / `projects.md`（那是知识，不是约束）
- 文件修改时间变化后自动重载

## 配置

```yaml
config:
  dir: '<记忆目录>'   # 省略则用 $DSH_HOME/memory
  limit: 3            # 最多几条
  minScore: 0.22      # 阈值
```

## 限制

- 按词面与动作匹配，不是语义理解；完全换说法可能匹配不到
- 中文按 bigram 切词，长段落会稀释分数
- 靠监听文档内 `contenteditable` 输入事件取草稿；宿主编辑器结构大改时可能失效（表现为"打字没反应"，不报错）

## 调试

设置环境变量 `MH_DEBUG=1` 可看到匹配过程中的查询分词与规则统计。
